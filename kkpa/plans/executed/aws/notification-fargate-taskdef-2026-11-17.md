## Sizing

**Recommended: `cpu 256` (0.25 vCPU), `memory 512` MB, `-Xmx256m`.**
- Same heap/limit ratio as the VPS (192m in 384 MB = 50%). 512 MB is the Fargate minimum for 0.25 vCPU.
- Low traffic: only invitation emails. CPU matters only at start (Hibernate + Liquibase).
- Start is slower than the VPS (0.25 vs 0.5 vCPU), so `startPeriod` is 120 s.
- Cost: about 9 USD/month per task (us-east-1). If start is too slow, go to `512 / 1024` (~18 USD).
- Desired count: 1 is enough. 2 only for zero-downtime during AZ failure.

Why each non-obvious value (goes into the doc, JSON has no comments):
- `DATABASE_URL` has **no query string**: the app appends `?currentSchema=notifications`. pgjdbc
  default `sslmode=prefer` uses TLS with RDS. `verify-full` would need a code change (known limit).
- `db-init`: Liquibase needs schema `notifications` before it starts. Advisory lock stops 2 tasks racing.
  If RDS is shared with the finance stack, its `db-init` already creates it; this one is still safe.
- `/tmp` volume: Fargate has **no tmpfs**. An empty task volume gives a writable `/tmp` with a
  read-only root, same as finance.
- `no-new-privileges` from compose has no Fargate field (`dockerSecurityOptions` is EC2 only). `cap_drop ALL` works.
- ECS health uses **`/q/health/live`** (no DB check), so a DB blip does not kill tasks. Consul keeps
  `/q/health` (readiness, with DB), so the gateway stops routing to a task that cannot reach the DB.
- `stopTimeout 30`: SIGTERM → the app deregisters from Consul → exits. `exec java` keeps java as PID 1.
- `ExitOnOutOfMemoryError`: an OOM ends the task, ECS starts a new one.
- `OTEL_SDK_DISABLED=true`: no collector on AWS yet (production observability is JBH-84).
- If the GHCR package is public, `repositoryCredentials` and the GHCR secret can go.

## IAM

**Execution role `jbh-notification-execution`** (used by ECS to start the task, not by the app):
- Managed `AmazonECSTaskExecutionRolePolicy` (CloudWatch Logs; ECR not used).
- Inline: `secretsmanager:GetSecretValue` on the GHCR, DB and SMTP secret ARNs only.
  Add `kms:Decrypt` only if the secrets use a customer-managed KMS key.
- Log group is created up front, so no `logs:CreateLogGroup`.

**Task role `jbh-notification-task`** (used by the app): the app calls **no AWS API**, so no policy.
Keep it only for ECS Exec (debug shell): `ssmmessages:CreateControlChannel`, `CreateDataChannel`,
`OpenControlChannel`, `OpenDataChannel`. Otherwise drop `taskRoleArn`.

## Network (security groups)

`jbh-notification` SG:
- Inbound `7778/tcp` from the gateway SG (traffic) and the Consul SG (health check). Nothing else.
- Outbound `5432` → RDS SG, `8500` → Consul SG, `465` + `443` → `0.0.0.0/0` (Gmail, GHCR via NAT).
- RDS SG: add inbound `5432` from `jbh-notification` SG.
- ECS service: private subnets, `assignPublicIp: DISABLED`, **no load balancer** (the gateway finds it
  through Consul, like on the VPS). Circuit breaker with rollback on. `minimumHealthyPercent 100`,
  `maximumPercent 200`.
